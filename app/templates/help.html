{{ icon('history', 18) }} Status meanings

Received
The Printer has dropped a file and it's queued to be processed.
Processing…
Blank pages are being stripped and the OCR/compression pass is running. This is the slowest step — a multi-page document can take a few minutes on a Pi 3B.
Uploading…
Only appears if cloud storage is enabled ({{ icon('cloud', 14) }} currently: {{ storage_provider }}) — the processed PDF is being copied to OneDrive.
Ready
Done. The scan is archived and viewable/downloadable from History, and if email is enabled ({{ icon('mail', 14) }} currently: {{ email_provider }}) the notification has been sent.
Failed
Something in the pipeline errored. The specific error is shown on the History row, and the original file is preserved for reprocessing.

{{ icon('alert-triangle', 18) }} Troubleshooting

A scan shows Failed
Check the error text on its History row — it's the actual exception message, not a generic code. The original file is kept so nothing is lost; once whatever's wrong is fixed, drop it back into the scan inbox to reprocess. Clear out old failures with the Clean Failed button on the History page.
The Printer can't reach the share / scan never arrives
Confirm the Pi is on the network and the Samba share is up (smb://<pi-ip-or-tailscale-name>/scans should connect from a laptop using the scanner account). If that works but scans still don't appear, check that the Printer's saved profile still has the right IP — it changes if the Pi's address isn't static/reserved.
No notification email arrives
{% if email_provider == 'none' %} Expected — email is currently turned off (EMAIL_PROVIDER=none). Check History instead. {% else %} First confirm the job actually shows Emailed on its History row — if not, the send itself failed and the error is in that row's message. If it says Emailed but nothing arrived, check spam, and confirm the recipient address on Settings is current. {% endif %}
